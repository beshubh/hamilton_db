# SQL statements

A user creates tables, writes rows and queries them in the Postgres dialect, and gets Postgres-style results: a row table with a `(N rows)` footer, a command tag, or a line starting `error:`.

## Sub-features

- `sql-ddl` creates a table with `INT`, `BIGINT`, `DOUBLE PRECISION`, `BOOL`, `VARCHAR(n)` and `TIMESTAMPTZ` columns, `NOT NULL` and a `PRIMARY KEY`.
- `sql-insert` inserts one or several rows and reports `INSERT n`.
- `sql-select` filters, orders, limits, joins and aggregates.
- `sql-update-delete` changes and removes rows and reports `UPDATE n` / `DELETE n`.
- `sql-identity` fills a `GENERATED BY DEFAULT AS IDENTITY` column from a sequence.
- `sql-truncate` empties a table, and `RESTART IDENTITY` resets its sequence.
- `sql-errors` rejects bad statements with a specific message and leaves the data unchanged.

## How to get to it (user POV)

- Pipe SQL into `hamilton-cli` (`hdb sql`).
- Type SQL at the `hamilton ❯` prompt (`hdb repl`, see [shell.md](./shell.md)).
- Run SQL from `psql -h 127.0.0.1 -p <port>` (`hdb psql`).

## Driving it with hdb

Preconditions:

- `hdb doctor` exits 0.
- No tables named `sq_items` or `sq_tags` exist (`\d` to check).

- **Create.** Run `hdb sql sql-ddl` with the block below. Output is `CREATE TABLE` twice, and `\d sq_items` lists six columns with types `INT`, `VARCHAR(16)`, `DOUBLE`, `BOOL`, `BIGINT`, `TIMESTAMPTZ`, `id` and `name` not nullable, and index `sq_items_pkey PRIMARY KEY (id)`.

  ```sql
  CREATE TABLE sq_items (id INT PRIMARY KEY, name VARCHAR(16) NOT NULL, score DOUBLE PRECISION, ok BOOL, big BIGINT, at TIMESTAMPTZ);
  CREATE TABLE sq_tags (id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, item_id INT, tag VARCHAR(8));
  \d sq_items
  ```

- **Insert and read back.** Run `hdb sql sql-insert`. Output is `INSERT 2`, then two rows ordered by id; row 2 shows empty cells for its NULLs and `false` for `ok`.

  ```sql
  INSERT INTO sq_items VALUES (1, 'a', 1.5, true, 10000000000, '2026-01-01 00:00:00+00'), (2, 'b', NULL, false, 2, NULL);
  SELECT * FROM sq_items ORDER BY id;
  ```

- **Update, delete, read back.** Run `hdb sql sql-update-delete`. Output is `UPDATE 1`, `DELETE 1`, then exactly one row `2 | b | 9`.

  ```sql
  UPDATE sq_items SET score = 9 WHERE id = 2;
  DELETE FROM sq_items WHERE id = 1;
  SELECT id, name, score FROM sq_items;
  ```

- **Identity.** Run `hdb sql sql-identity`. Output is `INSERT 2`, then rows `1 | 2 | x` and `2 | 2 | y`: the ids were generated.

  ```sql
  INSERT INTO sq_tags (item_id, tag) VALUES (2, 'x'), (2, 'y');
  SELECT * FROM sq_tags ORDER BY id;
  ```

- **Join and aggregate.** Run `hdb sql sql-select`. The join returns `b | x` and `b | y`; the aggregate returns `2 | 3`; the last query returns the single row `y`.

  ```sql
  SELECT i.name, t.tag FROM sq_items i JOIN sq_tags t ON t.item_id = i.id ORDER BY t.tag;
  SELECT count(*), sum(id) FROM sq_tags;
  SELECT tag FROM sq_tags WHERE id > 0 ORDER BY tag DESC LIMIT 1;
  ```

- **Truncate.** Run `hdb sql sql-truncate`. Output is `TRUNCATE TABLE`, a count of `0`, `INSERT 1`, then one row whose id is `1` again.

  ```sql
  TRUNCATE sq_tags RESTART IDENTITY;
  SELECT count(*) FROM sq_tags;
  INSERT INTO sq_tags (item_id, tag) VALUES (2, 'z');
  SELECT * FROM sq_tags;
  ```

- **Errors.** Run `hdb sql sql-errors`. Each statement prints one `error:` line, in order: `duplicate key value violates primary key sq_items_pkey`, `column name is not nullable`, `is too long for column name (max 16)`, `column nope does not exist`, `table missing does not exist`, `division by zero`. The final count is still `1`.

  ```sql
  INSERT INTO sq_items VALUES (2, 'dup', NULL, NULL, NULL, NULL);
  INSERT INTO sq_items VALUES (3, NULL, NULL, NULL, NULL, NULL);
  INSERT INTO sq_items VALUES (3, 'seventeen chars!!', NULL, NULL, NULL, NULL);
  SELECT nope FROM sq_items;
  SELECT * FROM missing;
  SELECT 1/0;
  SELECT count(*) FROM sq_items;
  ```

## Gotchas

- A failed statement doesn't stop the script and doesn't change the exit code. Read every block of output.
- `DROP TABLE` isn't supported (`error: not supported yet`). Use per-feature table names, or `hdb down && hdb up` for a clean database.
- Identity columns take `GENERATED BY DEFAULT AS IDENTITY`; `GENERATED ALWAYS` is rejected as not supported yet.
- A rolled-back or failed insert still consumes identity values, so ids can have gaps. Assert exact ids only right after `RESTART IDENTITY` or on a fresh table.
- `DOUBLE PRECISION` is displayed as `DOUBLE` by `\d`.
- Without `ORDER BY`, row order isn't part of the contract. Order every query whose rows you compare.
